Результатом выполнения задания является репозиторий, готовый к запуску командой `docker compose up -d`. В `README.md` должна находиться инструкция по работе с приложением.

# Лабораторная работа 3 — Повторяющиеся события

Фронтенд для бэкенда [`moscow-events`](https://github.com/nelkor/moscow-events),
позволяющий создавать серии повторяющихся событий по шаблону с заданным
интервалом и количеством повторений. Перед сохранением показывается
предпросмотр расписания с серверной проверкой каждого события.

## Что делает приложение

1. **Форма серии и шаблона события.** Название серии, название и
   описание события, артист, площадка, жанр, возрастная категория,
   цена, квота билетов, статус, длительность.
   Справочники артистов, площадок, жанров и возрастных категорий
   загружаются с бэкенда.
2. **Параметры расписания.** Дата и время первого события (в московском
   часовом поясе, UTC+03:00), длительность события в минутах, интервал
   (дни / недели / месяцы) и количество повторений (1–200).
3. **Предпросмотр.** Клиент строит расписание и сразу его отображает,
   затем отправляет тот же набор операций на сервер через
   `POST /api/v1/events/bulk` с `dry_run: true`. Сервер валидирует
   каждую операцию (существование артиста и площадки, квоты,
   интервалы и т.д.). Ошибки подсвечиваются рядом с соответствующими
   датами; сохранение блокируется, пока есть ошибки.
4. **Сохранение.** Создаётся серия (`POST /api/v1/series`), затем
   тот же набор операций с `series_id` применяется одной транзакцией
   через `POST /api/v1/events/bulk` с `dry_run: false` и
   `Idempotency-Key`. Если первая попытка не удалась, повторное
   нажатие кнопки переиспользует уже созданную серию и тот же ключ
   идемпотентности — дубликатов не будет.
